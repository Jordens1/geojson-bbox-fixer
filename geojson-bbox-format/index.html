GeoJSON bbox format and coordinate order

A two-dimensional GeoJSON bounding box uses [west, south, east, north]. The first two numbers locate the southwest corner and the last two locate the northeast corner. Each pair puts longitude before latitude.

Calculate a bbox from coordinates

Consider three points near San Francisco. Pick the westernmost and easternmost longitudes, then the southernmost and northernmost latitudes. The four bounds can come from different points.

{
  "type": "MultiPoint",
  "coordinates": [
    [-122.50, 37.78],
    [-122.42, 37.70],
    [-122.35, 37.82]
  ],
  "bbox": [-122.50, 37.70, -122.35, 37.82]
}

The first point supplies the west edge (−122.50°), the second the south edge (37.70°), and the third both the east and north edges. A collection’s bbox must enclose the coordinates of all its children.

Where elevation goes in a 3D bbox

For positions with elevation, each corner has three values. Write [west, south, lowest, east, north, highest]. For the points [10, 42, 85] and [11, 41, 120], the bbox is [10, 41, 85, 11, 42, 120]. The third and sixth values are elevations in metres.

When the east longitude is smaller than the west

Points at [179, 10] and [-179, 12] sit two degrees of longitude apart across the antimeridian. Their tight bbox is [179, 10, -179, 12]. Sorting the longitudes numerically would describe the other 358 degrees.

This example uses separate points. If a line or polygon crosses the dateline, RFC 7946 recommends cutting it there. A bbox change alone cannot split the geometry. See RFC 7946 on antimeridian cutting and antimeridian bounding boxes.

Check a declared bbox against a file

If a point falls outside a declared box, a spatial filter using that box can miss it. If every point is inside a larger box, decide whether that extra coverage is intentional before changing it. The GeoJSON bbox checker shows the declared and calculated values side by side.
